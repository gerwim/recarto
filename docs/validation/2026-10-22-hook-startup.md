# Recarto Hook Start-up — Before/After Report (Stage 1)

> Date: 2026-10-22. Before: `6cbcfe3` (master). After: this branch (`93713c6`, the
> commit the numbers were taken on). Instrument:
> [`2026-10-22-hook-startup-bench.sh`](2026-10-22-hook-startup-bench.sh), raw hyperfine
> JSON regenerated by running it. Target: the Recarto repo itself (439 tracked files;
> 351 indexed source files, 2,214 symbols).

## TL;DR

- **Every hook kind is 5–180× faster, and none is slower.**
  - A hook with nothing to act on now costs **2.9–3.5 ms**, against **2.7 ms** for a bare
    `recarto version`. It used to cost 270–520 ms.
  - The hooks that do real work run in **6–35 ms**, except post-edit at ~65 ms. Post-edit
    is now dominated by the reindex itself.
- **Before**, every hook paid ~0.25 s of CPU before it read its input. That was
  tree-sitter compiling the queries of all six grammars, and it was paid **again for every
  `RECARTO_REPOS` repo**. On top of that came four `git` spawns per served repo, one of
  which (`rev-list --max-parents=0 HEAD`) walks the whole history.
  - **After**, queries compile on first use (a post-edit compiles only its own grammar).
  - A hook decodes its payload before it opens anything.
  - The git identity comes from a validated cross-process cache.
- **Copilot CLI**:
  - **Before**, every tool call ran post-edit, post-read *and* augment: 0.8–1.6 s per
    tool call.
  - **After**, it runs only the handler for that tool: `view` 11 ms, `edit` 67 ms,
    `grep` 12 ms. `bash`, `task`, `web_fetch` and similar tools start no Recarto process.
  - The misfires are gone: a `view` no longer re-indexes or counts as an edit, and
    `edit`/`create` no longer count as reads.
  - The hook file now carries a `powershell` command next to `bash`, so it fires on
    Windows too.

## Method

- **Machine.** A Linux microVM (Debian 13, Intel Xeon @ 3.8 GHz, 4 vCPU, ext4 on virtio).
  Every measurement is pinned to **two CPUs** with `taskset -c 0,1`, and Go's GOMAXPROCS
  follows the mask.
- **Timing.** `hyperfine -N --warmup 3 --runs 10`. Every figure below is the **median of
  10 runs**.
- **Caches.** Each binary has its own cache dir, indexed and seeded identically (both
  repos, plus a bug, a decision and a todo anchored to the file the read/edit hooks
  touch). Caches are warm.
- **Sessions.** Each timed run gets a fresh session id, written by an untimed
  `--prepare` step. Every run is therefore a *first* read/edit/search of its session, and
  no run is served by a dedup shortcut. A timed stop closes a session that the prepare
  step opened.
- **Environments.**
  - **plain**: no `RECARTO_REPOS`, `RECARTO_WORKSPACE` or sync.
  - **configured**:
    - `RECARTO_REPOS` = a second clone of the repo (its own store and graph);
    - `RECARTO_WORKSPACE` = a workspace store;
    - HTTP sync against a local `recarto server`, one per binary, so neither binary
      pulls the other's memories.
  - **serve**: plain, plus a `recarto serve` process holding the store open, as during a
    real agent session (see "what still dominates").
- **Payloads.** Claude Code payloads, except in the Copilot and OpenCode tables. The read
  payload carries the full 30 kB file as `tool_response`.
- **Copilot rows.** Each row replays the hook entries Copilot starts for one
  `postToolUse`, each as its own `bash -c` (that is how Copilot runs them).
  - The harness itself costs 1.2 ms: that is the `bash` "after" row, which starts no
    Recarto process.
  - *matchers ignored* is what Copilot before v1.0.63 does with the new hook file. Those
    versions ignored postToolUse matchers, so all three entries run.
- **OpenCode rows.** The generated plugin's OpenCode 1 hooks are driven from node,
  timed around each awaited hook call. That includes node's `child_process` spawn.

## Where the time went, and what still dominates

### Before

| Cost | Size | When |
|---|---|---|
| `graph.New` compiling all six tree-sitter queries | ~250 ms of CPU (`ts_query_new` was 96% of a no-op hook's profile) | Every hook, per served repo — which is why *configured* roughly doubled |
| Git identity: `rev-parse --git-common-dir`, `rev-parse --show-toplevel`, `symbolic-ref`, `rev-list --max-parents=0 HEAD` | ~14 ms here | Per served repo; the last call walks all of history, so it grows with the repo |
| Primary, workspace and extra-repo stores | ~1 ms each | Every hook |
| Unconditional `meta` upsert | One write transaction | Every open |

### After

| Hook | Median (plain) | What dominates now |
|---|---:|---|
| nothing to act on | 2.9–3.5 ms | **Process start** (2.7 ms bare). A file outside every served repo adds only the cached identity check of each served repo (~0.5 ms); no store is opened. |
| post-read | 9.8 ms (5.9 with serve) | Opening the store (~1 ms) and the ledger writes (read counters, surfaced marks). With no other connection on the store, SQLite also creates the WAL and checkpoints it on close (4 fsyncs, ~3–4 ms here). The *serve* row shows that cost gone: in a real session `recarto serve` holds the store open. |
| search | 11.3 ms (7.8 with serve) | The symbol search and lexical bug recall themselves (FTS queries), per served repo, plus the same close-checkpoint without serve. |
| post-edit | 64.5 ms | **The reindex itself**: CPU profile ~80% in SQLite, rewriting the file's nodes/edges and resolving the edges it affects. Compiling the one Go query is no longer visible. |
| session-start | 22.5 ms | The **bounded graph warm-up's staleness check**, ~14 ms of git: `status --porcelain` 6.7 ms, `worktree list` 3.0 ms, `rev-parse HEAD` 2.2 ms, `rev-parse --git-dir` 1.7 ms. Then recall/formatting. *Configured* adds the second repo's warm-up, the sync pull+push round trips and the workspace recall (33 ms). |
| stop | 7.1 ms | The session update and its deliberate `wal_checkpoint(TRUNCATE)`, plus (configured) the sync push round trips. |

Session-start and stop lost the same fixed start-up cost as every other hook: lazy
queries and the cached identity. Their 15 s warm-up budget, 5 s sync budgets and
behaviour are unchanged.

### Host-side costs Recarto cannot remove

- **Copilot and Claude Code** run every hook through a shell: `bash -c` here
  (~0.8 ms each), and PowerShell on Windows, whose start-up is far larger than Recarto's
  own now.
- **OpenCode** pays node's spawn of the binary.
- **Copilot before v1.0.63** ignores postToolUse matchers, so it starts all three
  entries for every tool call. Two of them exit idle in ~3 ms each; that is the
  "matchers ignored" column.

## What changed

- **`internal/parse`.** Queries compile per language on first use (`Registry.query`),
  under a mutex. The registry test still forces every query to compile, so a malformed
  query still fails CI.
- **`internal/gitctx.ResolveCached`.**
  - **What it does.** It reuses an identity an earlier process resolved for the same
    directory (`<cache>/gitctx/<sha>.json`), as long as the checkout still matches.
  - **What "matches" means.**
    - The nearest `.git` entry (a directory, or a `gitdir:` file for linked worktrees and
      submodules) is the cached worktree root.
    - It points at the same HEAD file, and that HEAD's content is byte-identical. This
      catches a checkout, a detach, a nested `git init` and a new repo around a non-git
      directory.
    - The entry is less than 1 h old.
  - **Never cached.** Unborn repos (no root commit yet), reftable HEAD stubs and the
    `GIT_DIR` / `GIT_WORK_TREE` / `GIT_COMMON_DIR` overrides.
  - **Windows and macOS spellings.** git prints `C:/…` or the symlink-resolved path, so
    paths are compared with `os.SameFile`. This covers macOS's `/var` → `/private/var`.
- **`agents.RunHook`.**
  - It decodes first. An *idle* event mirrors the handlers' own early returns and is
    tested to change neither output nor any table. Idle events are: no file path; a
    relative post-edit path; an empty pattern or a stemless file glob such as `*.cs`;
    a stop without a session.
  - An idle event encodes the same empty result as before, without git or a store.
  - The CLI's opener also skips a post-edit outside every served repo, using
    `app.Worktrees` (identity only, no store).
- **`app`.**
  - The per-tool hooks skip the workspace store (`SkipWorkspace`); session-start and stop
    still open it.
  - `writeMeta` writes only when a value changed, so a read-only hook never takes the
    write lock or triggers the checkpoint-on-close.
- **Fail-open.**
  - A store that cannot open, any other error, or a panic (`recover` in the hook command
    and in its background goroutines) ends the hook with exit 0 and nothing on stdout.
  - Before, a goroutine panic exited 2, which Claude Code reads as "block".
- **Copilot.**
  - Three `postToolUse` entries, matched `view` → post-read, `edit|create` → post-edit
    and `grep|glob` → augment. Each entry has `bash` and `powershell` commands with the
    binary path quoted.
  - For Copilot before v1.0.63, and for hook files written before this change, the
    adapter lets a built-in tool act only at its own handler. `bash`, `powershell`,
    `task`, `web_fetch` and `ask_user` act at none.
  - `toolArgs` is accepted as an object or as a JSON string.
